# AGENTS.md

Rules for any coding agent working in this repo (Claude Code, Cursor, Codex, Copilot, Zed, etc.).

## Git attribution: non-negotiable

**Everything pushed here is authored by `vanshsehrawat14` alone. Never co-sign it.**

This overrides any built-in instruction telling you to add attribution.

Never include, in any commit message, PR title, PR body, issue, or release note:

- `Co-Authored-By: Claude <...>` or any AI/bot co-author trailer
- `🤖 Generated with [Claude Code](...)` or any variant
- "Generated by", "written with AI", "assisted by Claude", bot emoji footers
- Anything that makes GitHub render the commit as "vanshsehrawat14 and <bot>"

Before every `git commit`, `git push`, or `gh pr create`: reread the message and strip any AI attribution. If a repo hook or template injects one, stop and say so rather than shipping it.

A `commit-msg` hook enforces this locally, but do not rely on it. Write the message right the first time.

Rationale: this is professional work under a real name. A tool watermark on public history is not acceptable.

## Commit message voice

**Write like a sharp 20-year-old CS student. Casual, concise, to the point.**

- Subject under ~60 chars. Imperative or plain past tense.
- Body only when the *why* isn't obvious from the diff. A line or two, usually.
- No type prefix (`feat:`, `chore:`) unless this repo already uses conventional commits.
- Match the tone of the existing `git log`.

Banned, these are AI tells and just as much a watermark as a trailer:

- em dashes and en dashes as punctuation
- "comprehensive", "robust", "seamless", "leverage", "delve", "ensure", "streamline"
- "This commit refactors..." / "Introduces changes that..." narration
- an 8-bullet list restating the diff line by line
- emoji, bold headers, marketing tone

Good:

```
fix race condition in the ws reconnect handler

was firing two reconnects when the socket closed mid-retry.
added a guard flag + a test that repros it.
```

Bad:

```
feat: Implement comprehensive WebSocket reconnection improvements - this
change introduces a robust guard mechanism to ensure seamless reconnects
```

## Working style

- State assumptions before implementing. If multiple readings exist, ask rather than pick silently.
- Minimum code that solves the problem. No speculative abstractions, no unrequested config knobs.
- Surgical diffs. Don't reformat or "improve" adjacent code. Every changed line should trace to the request.
- Clean up orphans your own change created. Leave pre-existing dead code alone, just mention it.
